# Proposal

## Why

当前 MCP 只能识别物理组件是否存在，不能删除实体或从外部文件导入资源，单层撤销也不足以恢复连续编辑。扩展这些能力需要共同解决组件资源生命周期、实体恢复身份和可逆事务，使助手能在当前编辑会话内完成搭建、物理配置、删除及逐步恢复。

## What Changes

- 增加 `add_physics`、`set_physics`、`remove_physics`，查询完整物理配置，允许非播放状态下同步修改物理对象姿态。
- 增加 `delete_entity`，支持显式子树删除、完整快照、失败回滚和撤销恢复；无法完整恢复的组件明确拒绝删除。
- 将 MCP 单层撤销升级为有界多级撤销/重做，增加 `get_history` 和 `redo_operation`，保留原 `undo_operation` 调用方式。人工内容或资源修改以及外部编辑上下文变化清空历史；选择和截图保留历史。
- 增加 `import_asset`，对齐 Asset 窗口中的模型、二维纹理、音乐、音效及顶点/片元 Shader 导入，扩展资源查询；加载到当前会话，不复制源文件，不承担重启恢复。
- 扩展原子批次以容纳物理操作和实体删除；资源导入独立提交。所有新写入继续使用会话、revision、请求去重及结构化错误。
- 使用类型化操作记录、组件值快照和受控资源保留，支持跨删除恢复的历史依赖及稳定重做。

## Capabilities

### New Capabilities

- `editor-physics`: 非播放编辑场景中的物理配置查询、添加/修改/移除、姿态同步、校验与可逆生命周期。
- `editor-asset-import`: 当前会话的本地外部资源导入、依赖事务、资源键冲突及可逆登记。

### Modified Capabilities

- `editor-automation`: 扩展写入作用域、物理对象变换、资源查询、可恢复删除、原子批次和多级历史；保留旧目标失效与人工编辑冲突保护。
- `editor-mcp`: 扩展到 21 个工具，补充资源作用域写入、异步导入结果、历史查询与端到端验收契约。

## Impact

主要涉及 `EDITOR/src/editor/automation/`、桥接队列、物理属性面板和 Gizmo、`CORE` 的物理与资源管理、`RENDERING` 的加载器、`tools/engine_mcp/` 的生成契约/服务/演示、原生及 Python 测试和 VS 工程文件。现有 14 个工具的合法请求保持可用；撤销语义扩展，物理变换从拒绝改为有条件支持。Scene 图片协议、文件保存格式及手动操作的统一历史不在本次范围内。计划复用现有依赖，不增加模型服务、远程下载或新的资源格式库。
